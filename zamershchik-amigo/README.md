# Замеры Amigo — приложение для замерщиков

PWA для телефонов: замерщик снимает проём, выбирает ткань и модель, видит
**живую цену из вашего прайса** и отправляет заявку письмом на почту компании.

Цены, каталог тканей и правила подбора берутся не из воздуха — приложение ходит
в тот же API, что и веб-конфигуратор
[customizer.amigo.ru](https://customizer.amigo.ru): 12 систем, ~100 моделей,
418+ тканей с цветами и коллекциями.

```
телефон (PWA)  ──►  Node-сервер  ──►  Amigo Customizer API   (каталог + расчёт цены)
   │                    │
   │                    └──────►  SMTP ──► почта компании     (заявка с фото)
   └─────────────────────────────►  data/                     (история заявок)
```

Браузер звонит в Amigo напрямую не может — там закрыт CORS. Поэтому между
телефоном и Amigo обязательно стоит свой небольшой сервер.

---

## Деплой на Render + Supabase (бесплатно)

Приложение можно разместить в интернете, чтобы замерщики открывали его с телефона
по ссылке, а не через локальную сеть.

**Render** — бесплатный хостинг Node.js с автодеплоем из GitHub.
**Supabase** — бесплатная база PostgreSQL: у Render файловая система временная,
без базы заказы терялись бы при каждой пересборке.

### Шаг 1. Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (вход через GitHub).
2. Создайте проект (бесплатный тариф).
3. В SQL-редакторе выполните `scripts/supabase-schema.sql` — создаст таблицы
   `users`, `settings`, `orders`.
4. Скопируйте из настроек проекта (Project Settings → API):
   - **Project URL** → `SUPABASE_URL`
   - **service_role key** → `SUPABASE_KEY`

### Шаг 2. GitHub

1. Создайте репозиторий (например, `zamershchik-amigo`).
2. Загрузите в него код проекта.

### Шаг 3. Render

1. Зарегистрируйтесь на [render.com](https://render.com) (вход через GitHub).
2. **New → Web Service** → выберите репозиторий.
3. Runtime: **Node**, план **Free**.
4. Build Command: `npm install`, Start Command: `node server/index.js`.
5. В переменных окружения укажите `SUPABASE_URL`, `SUPABASE_KEY` и SMTP-ключи.
6. Нажмите **Create Web Service** — через пару минут приложение будет доступно
   по адресу вида `https://zamershchik-amigo.onrender.com`.

### Шаг 4. Проверка

1. Откройте ссылку на телефоне.
2. Войдите под замерщиком из `.env` (`BOOTSTRAP_NAME` / `BOOTSTRAP_PIN`).
3. Проверьте, что заявки сохраняются и письма уходят.

> Бесплатный тариф Render засыпает после 15 минут простоя — первый запрос
> поднимает сервис ~30–50 секунд. Для рабочего дня это обычно незаметно.

## 1. Что нужно

- **Node.js 18 или новее** — [nodejs.org](https://nodejs.org) (при установке
  отметьте галочку, чтобы работал `npm` из командной строки)
- Компьютер или сервер, который работает во время рабочего дня замерщика
- Ящик компании с паролем приложения (Яндекс / Google / Mail.ru)

Зависимостей всего две: `express` и `nodemailer`.

## 2. Установка

```bash
cd zamershchik-amigo
npm install
```

Скопируйте `.env.example` в `.env` и заполните:

| Что | Где взять |
|---|---|
| `SMTP_HOST`, `SMTP_PORT` | Яндекс: `smtp.yandex.ru:465` · Google: `smtp.gmail.com:465` · Mail.ru: `smtp.mail.ru:465` |
| `SMTP_USER`, `SMTP_PASS` | ящик компании и **пароль приложения** (в настройках ящика), не основной пароль |
| `MAIL_TO` | куда приходят заявки, можно два адреса через запятую |
| `PUBLIC_URL` | адрес, по которому открывают приложение, например `http://192.168.1.50:3000` |
| `BOOTSTRAP_NAME`, `BOOTSTRAP_PIN` | первый замерщик и его PIN |

`AMIGO_BASE` уже прописан на вашу копию конфигуратора — менять не нужно.

## 3. Проверка, что всё настроено

```bash
npm run check
```

Скрипт проверит `.env`, замерщиков, доступность каталога Amigo, пробный расчёт
цены и отправку почты. Всё зелёное — можно запускать.

## 4. Запуск

```bash
npm start
```

В консоли появится адрес вида `http://localhost:3000` и подсказка, с какого IP
заходить с телефона. Компьютер и телефон должны быть в одной сети (Wi-Fi).

Чтобы заявки приходили не только в вашей сети, поставьте сервер за nginx с
HTTPS и укажите реальный домен в `PUBLIC_URL`.

## 5. Замерщики и почта — прямо из приложения

Администратор управляет и сотрудниками, и адресом почты **из приложения**,
без правки файлов на сервере.

**Вход:** Профиль → «Администрирование».

### Сотрудники

Поле «Добавить замерщика»: имя и PIN от 4 до 8 цифр. PIN хранится в виде
хэша (scrypt) в `data/users.json` — в открытом виде его нет ни в одном файле.

Удаление сотрудника блокирует его вход сразу, при этом его прошлые заявки
остаются в истории — их по-прежнему видно и можно распечатать.

Две защиты от потери доступа:

- нельзя удалить самого себя
- нельзя удалить единственного администратора

### Адрес почты

Меняется получатель, отправитель и тема письма. Настройки лежат в
`data/settings.json` и **перекрывают `.env`**, поэтому применяются сразу,
перезапуск сервера не нужен.

`.env` задаёт только реквизиты самого почтового сервера (SMTP-логин, пароль,
хост) — их приложение не меняет, потому что это пароль.

Кнопка «Проверить» отправляет тестовое письмо на указанный адрес. Сразу видно,
дошло ли письмо и на тот ли ящик.

Кто что видит: администратор — все заявки, обычный замерщик — только свои.
Раздел администрирования доступен только с ролью `admin`.

### Плиссе и гофре: у моделей есть варианты

Системы «Шторы плиссе» и «Шторы гофре» устроены **двухуровнево**. В каталоге
видны семейства — «Модели MIDI», «Модели MAXI», «Модели MINI», «Модели RUS», —
но это не готовое изделие, а группа. У семейства **нет ни тканей, ни опций, ни
цены**; всё это лежит у конкретного варианта:

```
Шторы плиссе · Модели MIDI        ← 81 вариант, тканей 0
  └ P1600  00010829               ← 207 тканей, 2 опции, цена считается
  └ P1700  00010839
  └ …
```

Поэтому после выбора семейства приложение показывает отдельный шаг
**«1. Вариант модели»** — список с поиском по названию и артикулу. Дальше всё
идёт по id варианта: ткани, опции и расчёт.

Всего в каталоге **192 варианта** в семи семействах:

| Система | Семейство | Вариантов |
|---|---|---|
| Плиссе | Модели MIDI | 81 |
| Плиссе | Модели MAXI | 12 |
| Плиссе | Модели MINI | 2 |
| Плиссе | Модели RUS | 2 |
| Гофре | Модели MIDI | 81 |
| Гофре | Модели MAXI | 12 |
| Гофре | Модели RUS | 2 |

Поиск появляется, когда вариантов больше двенадцати. В заявке и письме видно и
семейство, и вариант: `Шторы плиссе · Модели MINI · P4612`, артикул `00017477`.

> Раньше эти семь семейств выглядели как «модели без тканей», и для них
> показывалась заглушка «цену посчитает офис». Она осталась на случай, если у
> какого-то варианта тканей в Amigo всё же не окажется.

### Авторизация в Amigo

В `.env` можно указать логин сотрудника-дилера:

```
AMIGO_LOGIN=ваш@логин.в.amigo.ru
AMIGO_PASS=пароль
```

Приложение возьмёт токен через `POST /api/get-token` и будет ходить в Amigo от
его имени. Токен кэшируется, при протухании обновляется автоматически. Если
вход не удался — работает как раньше, не падая. Бонусом придёт персональная
скидка дилера вместо базового прайса.

### Тип управления, крепление и режим замера

Опции подтягиваются из Amigo целиком — приложение показывает все, что вернул
каталог для выбранной модели. Проверено на всех 87 моделях: уникальных опций 33,
у самой насыщенной модели их 11.

**Важно про «Тип управления».** Значения «К управлению / От управления /
От центра» в каталоге есть — это опция `ТипУпр` («Открытие шторы»), но она
заведена **только для системы «Шторные карнизы»**. У вертикальных жалюзи во всех
пяти моделях Amigo отдаёт лишь две опции: `Управление` (Левое / Правое) и
`Длина управления`.

Поэтому для систем, где имя содержит «вертикальн», приложение показывает
отдельный блок **«Тип управления»** — та же ручная отметка, что и режим замера:
`К управлению`, `От управления`, `От центра`, `К центру`. Названия взяты те же,
что у Amigo, чтобы офис не путался. На цену не влияет, уходит в заявку и в
письмо строкой «Открывание: к управлению».

Если у модели есть настоящая опция `ТипУпр` (шторные карнизы), ручной блок
**не показывается** — иначе получилось бы два ответа на один вопрос. Там
работает каталожная опция.

Такого поля, как «замер по штапику или по стеклу», в Amigo **нет вообще** — ни
среди опций, ни среди параметров расчёта (`/api/calculate` принимает только
`model_id`, `width`, `height`, `quantity`, `material_id`, `options`). Поэтому в
приложении для рулонных штор, плиссе и гофре есть блок **«Как снят размер»**:

- что означает размер — **габарит изделия** или **размер ткани**;
- откуда снят — **по штапику** или **по стеклу**.

Это пометка для офиса, а не параметр расчёта: на цену она не влияет. Попадает в
заявку и в письмо отдельной строкой «Замер: габарит изделия · по стеклу», чтобы
при раскрое не перепутали сторону.

### Электрика для всех рулонных штор

Проверены все **48** рулонных моделей. Опции `Электропривод`, `Комплект
электрики` и `Тип привода` в каталоге Amigo есть **только у трёх** моделей:

```
Рулонные шторы / ZIP
Рулонные шторы / ZIP ROOF
Рулонные шторы / LOCK
```

У MINI, UNI, BNT, AMG, кассет, Зебры и Миража электрики в каталоге нет вообще —
выбрать её было нечем.

Поэтому для рулонных систем, где такой опции у модели нет, приложение
показывает блок **«Электрика»** с набором, взятым из Amigo дословно:

```
5. Электрика
   Электропривод:     [Нет] [Да]
   Комплект электрики [Нет] [DM35 (о/с, Wi-Fi)] [DM35 (провод)] [DM35 (рад, RS485)]
                     [DM35 (радио)] [DM35 (радио, о/с)] [DM45 (провод)] [DM45 (радио, о/с)]
```

У ZIP, ZIP ROOF и LOCK ручной блок **не показывается** — там работает каталожная
опция, дубли не возникает.

На цену электрика не влияет — см. следующий раздел. Выбор попадает в заявку и в
письмо строкой `Электрика: электропривод · комплект электрики Amigo DM35 (провод)`.

### Электропривод и комплект электрики не входят в цену

Опции `Электропривод` и `Комплект электрики` есть у трёх моделей — ZIP, LOCK и
LIFT система — и приложение их показывает полностью, со всеми значениями.

Но **на цену они не влияют**. Проверено напрямую через `/api/calculate` на ZIP
(артикул 00024499), 1500 × 2000 мм, без участия приложения:

| Что выбрано | Цена |
|---|---|
| ничего | 712,956 $ |
| привод Нет, комплект Нет | 712,956 $ |
| привод Нет, комплект DM45 (провод) | 712,956 $ |
| привод Да, комплект Нет | 712,956 $ |
| привод Да, комплект DM45 (провод) | 712,956 $ |
| привод Да, комплект DM35 (о/с, Wi-Fi) | 712,956 $ |

Разница строго нулевая. Это поведение Amigo, а не ошибка приложения: опции
уходят в расчёт, но в прайс не попадают.

Чтобы замерщик не ждал, что электрика уже посчитана, под ценой появляется
предупреждение:

```
Amigo не включает «Электропривод: Да; Комплект электрики: Комплект электрики
Amigo ZIP/LOCK DM35 (о/с,Wi-Fi)» в цену — доначислит офис.
```

Сами опции при этом попадают в заявку и в письмо — офис видит, что комплект
нужен, и начисляет его сам.

### Тип крепления рулонных штор

Проверены все **48** рулонных моделей (Рулонные шторы, Зебра, Мираж). В каталоге
Amigo у них 24 опции, но распределены они так:

| Опция | Сколько моделей |
|---|---|
| `Управление` — сторона (Левое / Правое) | 42 из 48 |
| `Цвет фурнитуры` | 31 из 48 |
| `Длина управления` | 41 из 48 |
| всё остальное | по 1–3 модели |

**Тип крепления** в этом списке есть только у двух моделей Зебры — это опция
`ТипУстановкиГИ` со значениями «На проём / на стену» и «В проём / на потолок».
У MINI, UNI, BNT, AMG, ZIP и LOCK её нет, хотя монтажнику она нужна всегда.

Поэтому приложение показывает блок **«Тип крепления»** для рулонных систем с
теми же двумя значениями — дословно как в Amigo. Если у модели уже есть своя
опция `ТипУстановкиГИ`, ручной блок **не показывается**: у `Зебра BNT классика L
Double` в списке опций есть «Тип установки», и дубли не возникает.

Как и остальные ручные отметки, на цену не влияет — уходит в заявку и письмо
строкой «Крепление: в проём / на потолок».

### Каталог тканей сворачивается

Каталог — это до 400 тканей, то есть несколько экранов. Выбрали ткань — он
схлопывается в одну строку, а размеры оказываются прямо под ней, без прокрутки:

```
1. Ткань
┌────────────────────────────────────────────────┐
│ [образец] ЛИНА BLACK-OUT 2259 магнолия   Заменить│
│            бежевый                             │
└────────────────────────────────────────────────┘
2. Размер изделия
```

Тап по строке разворачивает каталог обратно. Пока он раскрыт и ткань уже выбрана,
сверху висит кнопка «← Выбрана: … — свернуть».

Данные тканей и опций кэшируются в памяти экрана, поэтому переключение не
мигает экраном загрузки. При смене модели кэш сбрасывается.

У моделей без тканей («Шторы плиссе», «Шторы гофре») каталога нет вообще — вместо
него напоминание, что цену посчитает офис.

### После ткани — сразу к размерам

Когда каталог сворачивается, размеры всё равно могут оказаться за краем экрана.
Поэтому страница прокручивается к блоку размеров, а курсор встаёт в поле ширины.

Фокус ставится с `preventScroll`, иначе браузер сам дёрнул бы страницу и поле
оказалось под липкой панелью расчёта.

### Стоимость монтажа

В каждой позиции заявки есть поле **«Монтаж»** — сумма в рублях, которую замерщик
вводит сам. В прайсе Amigo монтажа нет, и курсом он не пересчитывается.

Считается **за позицию целиком**, а не за штуку: вписали 2 500 ₽ при трёх
шторах в строке — получится 2 500 ₽, а не 7 500. Умножать на количество нужно
заранее, если так считает офис.

В итогах монтаж показан отдельной строкой, чтобы было видно, из чего собрана
сумма:

```
Изделия, 3 шт.    5 171,90 ₽
Монтаж            3 500,00 ₽
Итого             8 671,90 ₽
```

Сервер принимает только число от 0 до 10 000 000, мусор и отрицательные значения
превращает в ноль. В письме монтаж идёт строкой в каждой позиции и отдельной
строкой в итогах — офис видит и общую сумму, и из чего она сложилась.

### Длинные списки и «всё равно в заявку»

У Mono-систем (`AMG классика Mono`, `BNT классика L Mono` и подобные) есть
опции «Ткань 2-го изделия» и «Ткань 3-го изделия» — по 444 и 445 тканей. Такие
списки показываются выпадающим списком, а не кнопками: кнопок получилось бы
на два экрана.

Есть модели, для которых Amigo считает только при полном наборе параметров.
Например, у `AMG классика Mono` обязательны ширина и высота второго изделия —
без них приходит «Ошибка вычисления стоимости изделия». Раньше это намертво
блокировало кнопку «В заявку», и замерщик не мог отправить замер вообще.

Теперь при ошибке расчёта рядом появляется кнопка **«Всё равно в заявку — цену
посчитает офис»**. Позиция попадает в заявку с пометкой «цена в офис», а сервер
в письме добавляет предупреждение с текстом ошибки от Amigo.

### Много изделий в одной заявке

Ограничений нет: сколько угодно позиций из разных систем, моделей и тканей,
количество у каждой — любое. Кнопка «+ Добавить ещё изделие» в заявке ведёт
обратно в каталог.

В карточке «Клиент» есть переключатель **«Клиент — юридическое лицо»**. Когда он
включён, появляется блок загрузки реквизитов: достаточно сфотографировать или
загрузить скан — отдельные поля ИНН и расчётного счёта вводить не нужно.

Реквизиты едут вместе с заявкой как отдельный файл и в письме попадают в
собственный блок **«Реквизиты юридического лица»**, а не в «Фото с замера».
Офису не приходится гадать, где документ, а где снимок окна.

Технически фото помечаются видом: `requisites` — реквизиты, `opening` — проём.
Если заявка на организацию, а реквизиты не приложены, письмо содержит об этом
прямое предупреждение — чтобы офис не выставил счёт вслепую.

Фото уменьшается перед отправкой (реквизиты — до 1600 px), чтобы заявка уходила
быстро даже в слабой сети.

### Вход: сначала выбираешь себя

При входе приложение спрашивает, кто заходит, и только потом — PIN. Это нужно
затем, что **PIN проверяется у выбранного человека**, а не у первого, у кого
он совпал. Если у двух сотрудников случайно одинаковый код, каждый всё равно
войдёт под своим именем.

Секретом остаётся сам PIN: список сотрудников виден любому, кто открыл
приложение, но войти без кода нельзя.

Появившийся список берётся из `GET /api/login/users` — он специально открыт
без авторизации.

### Профиль замерщика

Вкладка «Профиль» → «Мои данные». Замерщик сам меняет своё имя и почту.

**Смена PIN** требует ввода текущего кода: телефон может оказаться
разблокированным, и без проверки любой смог бы сменить пароль. После смены
сессия закрывается — нужно войти с новым PIN.

При смене PIN старая соль заменяется, поэтому старый хэш больше не подходит.

### Почта замерщика

У каждого замерщика есть свой адрес для ответов. Само письмо отправляется
**с ящика компании** — почтовые серверы не позволяют подделывать отправителя.
Почта замерщика ставится в письмо как **Reply-To**: менеджер нажимает «Ответить»
и пишет напрямую замерщику. Адрес также печатается в шапке письма.

### Что может администратор

В карточке каждого сотрудника меняются имя, почта, PIN и права:

| Право | Что видит |
|---|---|
| Замерщик | только свои заявки |
| Администратор | всё приложение, включая раздел администрирования |

Пустое поле PIN означает «оставить как есть» — при заполнении соль
перегенерируется.

Защиты от потери доступа:

- нельзя удалить самого себя
- нельзя удалить единственного администратора
- нельзя снять права у единственного администратора

Из командной строки то же самое:

```bash
npm run pin -- --name "Иван" --pin 4321   # добавить
npm run pin -- --list                      # список
npm run pin -- --delete "Иван"              # удалить
```

## 6. Установка на телефон

Откройте адрес в Chrome и выберите **«Установить приложение»** (или «На экран
Домой» на iPhone). Появится иконка, приложение откроется без адресной строки и
браузерных кнопок. Интернет нужен только при первом открытии.

## 7. Как это выглядит в работе

1. **Каталог** → система («Рулонные шторы», «Шторы плиссе», «Портьеры и римские
   шторы»…) → модель.
2. **Ткань** — сетка с образцами и названием коллекции, есть поиск.
3. **Размер** — ширина и высота в миллиметрах, количество.
4. **Опции** — цвет фурнитуры, сторона управления и всё, что настроено для
   модели в Amigo.
5. **Живой расчёт** — цена появляется сразу, как только введены размеры.
   Ниже показывается площадь и подсказки системы («Выберите материал»,
   «Введите размеры!»), а при ошибке кнопка блокируется.
6. **Заявка** — несколько изделий в одной заявке, данные клиента, фото проёмов
   с камеры, комментарий.
7. **Отправка** — письмо на почту компании со всеми позициями, ценами, фото
   внутри письма и отдельным файлом-спецификацией.

## 8. Про деньги: почему на экране рубли, а в прайсе доллары

Прайс в системе Amigo ведётся в **долларах**. Это видно по её собственным
отчётам — они так и подписаны: «На сумму, USD», «Наценка, USD».

Ловушка: на анонимный запрос `POST /api/calculate` сервер отвечает
`currency_code: "RUB"`. Это **валюта по умолчанию для гостя**, а не валюта
вашего прайса. Если поверить этой метке, изделие за 1200×1500 мм покажется
как 36 ₽ вместо 3 023 ₽.

Поэтому приложение метку из ответа игнорирует и переводит явно:

| Что | Откуда |
|---|---|
| Цена в долларах | `POST /api/calculate` |
| Курс | официальный курс ЦБ РФ, обновляется сам, ключи не нужны |
| Сумма в рублях | цена × курс, на экране у замерщика |

Подпись под ценой показывает и доллары, и курс — чтобы сверить расчёт и сразу
заметить, если что-то пошло не так.

Настройки в `.env`:

| Параметр | Значение |
|---|---|
| `PRICE_SOURCE_CURRENCY` | валюта прайса, `USD` |
| `PRICE_TARGET_CURRENCY` | что показываем, `RUB` |
| `RATE_PROVIDER` | `cbr` — курс ЦБ автоматически, `manual` — только из `USD_RATE` |
| `USD_RATE` | свой курс. Как только задан — важнее автоматического |
| `RATE_TTL_HOURS` | сколько часов держать курс (ЦБ обновляет раз в сутки) |

Курс едет вместе с заявкой: в письме видно, по какому курсу посчитано и за
какую дату. Если ЦБ РФ в момент отправки недоступен, письмо уходит по
последнему удачному курсу с пометкой «данные не удалось обновить» — заявка не
теряется.

Если вдруг окажется, что ваш прайс уже в рублях, достаточно поменять
`PRICE_SOURCE_CURRENCY=RUB` — пересчёт отключится сам.

## 9. Что с ценой

Цену считает **Amigo**, а не телефон. Клиент присылает только размеры и свой
выбор — сервер сам пересчитывает каждую позицию перед отправкой заявки. Поэтому
подделать цену из браузера нельзя, и в письме всегда стоит актуальная цифра.

Учтите: без входа в учётную запись Amigo API отдаёт базовый прайс, без персональной
скидки дилера. Если скидки нужны — это отдельная доработка (передача токена
сотрудника), см. раздел «Что дальше».

## 10. Если нет связи

Заявка не теряется: она сохраняется на телефоне (IndexedDB) и уходит сама, как
только появится интернет. Неотправленные заявки видны в «Истории» → «Ждут
отправки». Там же — кнопка «Отправить письмо снова», если письмо не ушло,
например, ящик был недоступен.

## 11. Где лежат данные

```
data/
├── users.json          замерщики (PIN в виде хэша)
├── orders.jsonl        заявки, по одной на строку
└── photos/AM-…/        фотографии проёмов
```

Всё это — обычные файлы: заявки можно выгрузить в Excel, бэкапить копированием
папки, история заказов не пропадёт при переезде на другой хостинг.

## 12. Код

Посмотреть интерфейс **без установки Node** можно через макет сервера на
PowerShell — см. `tools/README.md`:

```powershell
powershell -ExecutionPolicy Bypass -File tools\mock-backend.ps1 -Port 8787
```

Открыть `http://127.0.0.1:8787/`, PIN `1234`. Каталог и цены — настоящие,
из Amigo. Заявки при этом не отправляются.

```
server/
├── index.js           маршруты: вход, каталог, расчёт, заявки
├── amigo.js           клиент Amigo API: каталог, ткани, опции, расчёт
├── auth.js            вход по PIN, хэширование, токены
├── settings.js        адрес получателя почты (перекрывает .env)
├── store.js           заявки в orders.jsonl
├── photos.js          фото на диск
├── order-template.js  вёрстка письма
├── currency.js        курс USD→RUB (ЦБ РФ или свой)
├── mailer.js          отправка через SMTP
└── config.js          настройки из .env
public/                приложение на телефоне (без сборки, чистый JS)
scripts/
├── set-pin.mjs        управление замерщиками
├── selfcheck.mjs      проверка окружения
├── make-icons.mjs     генерация иконок (Node)
└── make-icons.ps1     то же самое на PowerShell, если Node ещё нет
tools/                 стенды для разработки, в работу не попадают
```

Фронтенд — обычные файлы без сборщика: правьте `public/app.js` и обновляйте
страницу. Данные из Amigo кэшируются на 30 минут (`CATALOG_TTL_SEC`), кнопка
«Профиль» показывает актуальность через сброс кэша.

## 13. Что дальше (по приоритету)

1. **Заявка прямо в Amigo** — сейчас она только письмом. Добавим создание
   заказа через `POST /api/orders` с токеном сотрудника, чтобы замерщик не
   дублировал работу менеджеру.
2. **Скидка дилера** — вход по логину Amigo вместо PIN, тогда цены придут с
   персональной скидкой.
3. **Смета и договор** — печать бланка замера прямо из приложения.
4. **Оффлайн-каталог целиком** — сейчас в кэш попадает только то, что уже
   открывали; можно заранее скачивать ткани нужной модели.
5. **Яндекс.Карты** — вбить адрес и показать маршрут до объекта.
